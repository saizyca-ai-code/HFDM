## Warm cache and resume

- HF Model balanced cache-hit download step: 0.0102–0.0261 seconds, 3/3 `available`. These times are cache checks, not network throughput.
- Civitai: 3/3 runs intentionally interrupted at 512 MiB, then resumed from exactly 512 MiB and completed SHA256 verification. Corrected remaining-transfer rates were 50.81, 52.99, and 42.09 MiB/s.

## Measurement notes

- The first 12 Dataset worker runs exposed missing hf_xet tqdm/RSS instrumentation. Their JSON is retained but excluded. A separately named instrumented 12-run set is used above.
- HF TTFB is based on first growth in the dedicated destination/Xet cache because hf_xet does not consistently emit Python tqdm progress.
- HF file-growth peak can include cache/reconstruction copy bursts and is not treated as network peak or used for decisions.
- Public HF requests were unauthenticated and emitted rate-limit warnings; this is recorded as an environmental limitation.
- The raw benchmark tree contains 69 JSON artifacts and 66.82 GiB of data. It is intentionally retained for verification and is outside the repository and HFDM production directories.

## Proposed V2 defaults

- HF profile: `balanced`.
- Dataset/global concurrent file workers: `8` (supported upper limit remains `16`).
- Civitai segments: `1` (supported upper limit remains `8`).
- Keep `maximum` and `hdd` as explicit opt-in profiles; do not auto-select `maximum`.

Production defaults are not changed until the user confirms this result set.
